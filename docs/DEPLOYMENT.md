# Deploying FIN-SCOPE

The free-tier setup:

| Piece | Service | What it hosts |
| --- | --- | --- |
| Database | **Neon** (free) | PostgreSQL |
| Cache | **Upstash** (free) | Redis (only used for the health check today) |
| API | **Render** (free web service, Docker) | `apps/api` via `apps/api/Dockerfile` |
| Web | **Vercel** (Hobby) | `apps/web` |
| Payments | **Razorpay** (TEST mode) | Test orders and signed webhooks |

Allow about 30–45 minutes the first time. Dashboard button names change from
time to time; if a label differs slightly, look for the closest match.

```
Browser ──► Vercel (Next.js pages + /api/* route handlers, server-only API_KEY)
                 │  X-API-Key
                 ▼
            Render (FastAPI) ──► Neon Postgres
                 │          └──► Upstash Redis
                 ├──► Anthropic API (reasoning step only)
                 └──► Razorpay TEST API ◄── Razorpay webhooks (HMAC-signed)
```

Before you start, merge the `polish/ui-and-deploy` branch into `main` (or
choose that branch wherever a step below asks for one).

---

## 0. Generate one shared secret

The web app and the API share one secret, `API_KEY`. Either let Render
generate it (step 3) and copy it from there, or create one yourself:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

Keep it somewhere safe. It goes in exactly two places: Render (`API_KEY`) and
Vercel (`API_KEY`). It must never go in a `NEXT_PUBLIC_*` variable or in git.

---

## 1. Postgres on Neon → `DATABASE_URL`

1. Go to <https://neon.tech>, sign in, and click **New project**.
   - Name: `fin-scope`
   - Postgres version: 16 (or the default)
   - Region: pick the one closest to your Render region (e.g. **AWS Asia Pacific (Singapore)**)
2. On the project dashboard click **Connect**.
3. Choose the default branch, database `neondb` and the default role. Turn **Connection pooling OFF** to get the *direct* connection string. The app uses SQLAlchemy's own pool, and Alembic migrations should not go through PgBouncer.
4. Copy the string. It looks like:
   ```
   postgresql://neondb_owner:AbC123@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```
5. **Change the scheme to the driver the app uses**, `postgresql+psycopg://`:
   ```
   postgresql+psycopg://neondb_owner:AbC123@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```
   Keep `?sslmode=require` (and `&channel_binding=require` if Neon added it). This final string is your **`DATABASE_URL`**.

---

## 2. Redis on Upstash → `REDIS_URL`

1. Go to <https://console.upstash.com>, sign in, and open **Redis → Create database**.
   - Name: `fin-scope`
   - Type / region: a single region near your API (e.g. `ap-southeast-1`)
   - Plan: **Free**
2. Open the database. Under **Connect**, choose the **redis-cli / TCP** tab (not REST) and copy the TLS URL:
   ```
   rediss://default:YOUR_PASSWORD@your-db-12345.upstash.io:6379
   ```
   Note the **`rediss://`** (two s's = TLS). This is your **`REDIS_URL`**.

## 3. API on Render

### 3a. Create the service from the blueprint

1. Go to <https://dashboard.render.com> → **New** → **Blueprint**.
2. Connect GitHub if asked and pick **indhuja-elumalai/fin-scope**, branch `main`.
3. Render reads `render.yaml` and shows one service, **fin-scope-api** (Docker, free plan, Singapore). Click **Apply** / **Deploy Blueprint**.
4. Render asks for every value marked `sync: false`. Fill them in:

| Key | Value |
| --- | --- |
| `DATABASE_URL` | the `postgresql+psycopg://…` string from step 1 |
| `REDIS_URL` | the `rediss://…` string from step 2 |
| `ANTHROPIC_API_KEY` | your Anthropic key (or leave empty: reasoning then shows "unavailable"; see section 7) |
| `ANTHROPIC_WORKSPACE_ID` | **required if your key starts with `sk-ant-usr`** (a user-scoped key): the workspace ID from Console → Settings → Workspaces, e.g. `wrkspc_…`. Without it Anthropic rejects every request. Leave empty for a normal workspace key |
| `RAZORPAY_KEY_ID` | `rzp_test_…` (**test** key only) |
| `RAZORPAY_KEY_SECRET` | the matching test secret |
| `RAZORPAY_WEBHOOK_SECRET` | any strong string; you will paste the same value into Razorpay in step 5 |
| `RAZORPAY_TEST_MODE_CONFIRMED` | `true` (only after double-checking the key starts with `rzp_test_`) |
| `RAZORPAY_DEFAULT_MERCHANT_ID` | leave empty for now; filled in at step 3c |

These are already set by the blueprint:

| Key | Value |
| --- | --- |
| `ENVIRONMENT` | `production` (turns on strict CORS) |
| `CORS_ALLOWED_ORIGINS` | `https://fin-scope-tawny.vercel.app`. Comma-separate extra origins, no trailing slash |
| `API_KEY` | generated by Render. Open **fin-scope-api → Environment**, reveal it, and copy it for Vercel |

Optional: `ANTHROPIC_MODEL` and `ANTHROPIC_TIMEOUT_SECONDS` (see `.env.example`).

5. Wait for the first deploy. The logs should show:
   ```
   [entrypoint] applying database migrations
   INFO  [alembic.runtime.migration] Running upgrade  -> 0001 ...
   ...
   [entrypoint] starting API on port 10000
   ```
6. Your API URL is shown at the top of the service page, e.g.
   `https://fin-scope-api.onrender.com`. If Render gave you a different
   subdomain, use that everywhere below and update the API docs link in
   `README.md`.

Quick check:

```bash
curl https://fin-scope-api.onrender.com/health
# {"status":"ok","checks":{"database":{"status":"ok"},"redis":{"status":"ok"}}}
```

### 3b. Load the demo data (run once, from your laptop)

Render's free tier has no shell, so run the seed script locally against the
production database. It only talks to Postgres:

```bash
cd apps/api
source .venv/bin/activate          # dependencies from the README quick start
DATABASE_URL='postgresql+psycopg://…neon…?sslmode=require' \
REDIS_URL='rediss://default:…@….upstash.io:6379' \
API_KEY='same-value-as-render' \
python scripts/seed_demo.py
```

To include **one real Claude reasoning result per incident** (it is stored, so
visitors see it without triggering new calls), add your key and the flag:

```bash
ANTHROPIC_API_KEY='sk-ant-…' ANTHROPIC_WORKSPACE_ID='wrkspc_…' \
DATABASE_URL='…' REDIS_URL='…' API_KEY='…' \
python scripts/seed_demo.py --reasoning
```

(`ANTHROPIC_WORKSPACE_ID` is only needed for user-scoped `sk-ant-usr…` keys.)

The script is idempotent, so running it again changes nothing.

### 3c. Point Razorpay webhooks at a merchant

Every verified Razorpay webhook is attributed to one FIN-SCOPE merchant.

1. Open the deployed site → **Merchants** and copy the ID of the merchant
   that should receive Razorpay events (e.g. *Aurora Retail (demo)*), or
   create a new one such as "Razorpay Test Account".
2. In Render → **fin-scope-api → Environment**, set
   `RAZORPAY_DEFAULT_MERCHANT_ID` to that UUID and save. Render redeploys.

## 4. Web on Vercel

The project already exists (`fin-scope-tawny.vercel.app`).

1. <https://vercel.com> → open the project → **Settings → General**.
   - **Root Directory**: `apps/web`
   - Framework preset: Next.js (auto-detected)
2. **Settings → Environment Variables**. Add these for **Production** (and Preview if you use preview deploys):

| Key | Value | Notes |
| --- | --- | --- |
| `API_BASE_URL` | `https://fin-scope-api.onrender.com` | Server-only. No trailing slash |
| `API_KEY` | the same value as Render's `API_KEY` | Server-only. **Never** prefix with `NEXT_PUBLIC_` |
| `NEXT_PUBLIC_API_BASE_URL` | `https://fin-scope-api.onrender.com` | Public URL only (no secret). The app falls back to it if `API_BASE_URL` is missing |

3. **Settings → Git**: make sure the production branch is `main`.
4. **Deployments** → open the latest → **Redeploy** (environment variables only apply to new deployments).

The browser never talks to Render directly. Pages call `/api/*` on Vercel, and
those route handlers add the `X-API-Key` header on the server.

## 5. Razorpay TEST webhook

1. <https://dashboard.razorpay.com> → switch the top-bar toggle to **Test Mode**.
2. **Account & Settings → Webhooks** (on older dashboards: **Settings → Webhooks**) → **Add New Webhook**.
   - **Webhook URL**: `https://fin-scope-api.onrender.com/v1/webhooks/razorpay`
   - **Secret**: exactly the value of `RAZORPAY_WEBHOOK_SECRET` on Render
   - **Active events**: `payment.captured`, `payment.failed`, `order.paid` (the three the API maps; anything else is acknowledged and ignored)
3. Save. Razorpay signs each delivery with `X-Razorpay-Signature`, and the API rejects anything with a bad signature.

To see a delivery: run an investigation to an **ALLOWED** decision, click
**Create Razorpay TEST order**, pay it with a Razorpay test card from their
docs, then click **Verify Razorpay TEST outcome** once the webhook has arrived.

- [ ] `https://fin-scope-tawny.vercel.app` top bar shows **API ONLINE** next to **TEST ENV**.
- [ ] **Command center** shows 3 merchants, 3 investigations, 2 incidents and *All systems nominal* (after seeding).
- [ ] **Merchants** lists the three demo merchants.
- [ ] **Events** lists 21 demo events, and the merchant and type filters work.
- [ ] Opening an event shows its fields and raw payload.
- [ ] **Investigations → Aurora Retail (demo)** shows the control-loop stepper with Find through Verify complete (Reason too, if you seeded with `--reasoning`), a **POLICY · ALLOWED** authorization, an executed sandbox action and an outcome verification.
- [ ] **Northwind Travel (demo)** shows **POLICY · REQUIRES HUMAN APPROVAL** with its reasons and no *Execute in sandbox* button.
- [ ] End to end on a fresh merchant: create a merchant → ingest 3 `payment_failed` events with small INR amounts → run an investigation → (optional) *Run reasoning* → *Run simulation* with *Retry affected payments* → *Evaluate scenarios* → *Execute in sandbox* → *Verify outcome*.

## 7. Keeping a public demo cheap and safe

Render's free web services sleep after about 15 minutes without traffic, and the
next request takes **30–60 seconds** to wake them. Meanwhile the top bar shows
**API OFFLINE** and pages show a "could not reach the API" or "failed to load"
message; reloading after a minute fixes it. To warn visitors up front:

- Keep the note at the top of the README ("first request can take 30–60 s").
- Optionally add the same line to the Vercel project description or your portfolio link text.
- If you don't want visitors to wait, have an uptime pinger (e.g. a free cron monitor) hit `/health` every 10–14 minutes. This uses free-tier hours, so check Render's current monthly allowance first.

**Cost and abuse controls.** Anyone with the link can press buttons, so:

1. **No code change needed (recommended for now):** leave `ANTHROPIC_API_KEY`
   and the Razorpay keys **unset on Render**, and seed once from your laptop
   with `--reasoning` (step 3b). Visitors see a real, stored Claude result.
   New reasoning requests are recorded as "unavailable" and Razorpay actions as
   "rejected", both without any external call, using the code paths that
   already exist. Add the keys back only when you are presenting live.
2. Use a separate Anthropic workspace with a low monthly spend limit for the
   demo key, and Razorpay **test** keys only (enforced by the code anyway).
3. A `DEMO_MODE` flag and request rate limiting are proposed in the pull
   request description. They are not implemented, because they change backend
   or proxy behaviour.

## 8. Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Every page shows "could not be loaded" with HTTP 401 | Vercel's `API_KEY` differs from Render's | Make them identical and redeploy Vercel |
| "Failed to load … (502)" or "The FIN-SCOPE API could not be reached" | Render service asleep or crashed | Wait about a minute and reload; check Render logs |
| Reasoning: "returned an error (HTTP 400/401)" | User-scoped key without `ANTHROPIC_WORKSPACE_ID`, or a revoked key | Set `ANTHROPIC_WORKSPACE_ID`, or create a new key |
| Reasoning: "provider is not configured" | `ANTHROPIC_API_KEY` not set on Render | Add it and let Render redeploy |
| Razorpay action "rejected" | Keys missing, not `rzp_test_…`, or `RAZORPAY_TEST_MODE_CONFIRMED` is not `true` | Fix the three variables |
| Razorpay verification "insufficient observation" | No webhook received for that order yet | Check the webhook URL, secret and events in Razorpay (step 5) |
